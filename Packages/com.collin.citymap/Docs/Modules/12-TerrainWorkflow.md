## 1. 用户三段式 ↔ 现有管线（结论：不违反 §3.2 重放契约）

用户要的工作流：
```
① 生成地图，仅参数
② 平面地图 + 山水雕刻 + 噪音随机生成          （创作"自然地表"）
③ 平整地块，形成地表数据                        （城市读地表、能压则压、太陡则弃）
```
映射到现有阶段（`PipelineRunner.ExecutionOrder`）：

| 用户步骤 | 现有阶段 | 说明 |
|---|---|---|
| ① 仅参数 | `CityProject` 世界参数 + `CityGrid` | M1 已交付 |
| ② 平面+噪音 | `S1a`（`baseAmplitude=0` 即纯平面；>0 即"噪音随机生成"）| 平面是噪音幅度的**特例**，一个旋钮覆盖，无需新概念 |
| ② 山水雕刻 | `S2` 河流下切（水）+ `SculptDelta` 人工笔刷（山）| 原 DESIGN **M3/M6** 的工具，**提前** |
| ③ 平整地块 | `S1b` 平整约束融合 + `S4` 地块 | M2 的 8x 强约束即"中坡压平" |

§3.2 重放次序 `h_base → carve → sculpt delta → flatten` **原样成立**：
"雕刻在平整之前"是契约第 3→4 步的既有语义（**先**把人工层叠进工作数组，**再**平整）。

> ⚠️ **更正（2026-11-04）**：本节早期版本声称"人工钉住的格由 `ManualLocked` 豁免、不被自动平整抹回"——
> **该机制不存在**，是我写下的不实描述。真实后果：`ManualLocked` 只是**地块掩码词表里的一个位**，
> S1b 的自动平整**从不检查它**，且城内 8× 强约束的拟合目标读的是"含雕刻的意图地表"，
> 刚抬的山会被当场拟合压回平面 ⇒ 用户实机反馈②「笔刷抬了没反应」的**结构性根因**。

**落地机制 = 阶段闸门（不是逐格退让）**：`CityTerrain.FlattenEnabled`（默认开）。
关闭时 S1b 在 `CommitBaseAsWorking() + Delta.ApplyTo()` **之后**、收集约束**之前**整段短路
（`Outputs=0`、不生成任何约束），工作数组停在"噪声基底 + 人工雕刻"的意图地表上直接交出。

| 用户三段 | 阶段闸门状态 | 画面 |

| ① 仅参数 | — | 未生成 |
| ② 雕山水（噪音+笔刷） | `FlattenEnabled=false` | 意图地表，平整**完全不介入** ⇒ 抬多少看见多少 |

用户 2026-11-04 明确否决"逐格退让"方案（原话：*自动平整还是要执行，但它不应该在雕刻时阻碍我；

### 1.1 步骤条交付后仍不可用的真因（M4-i，2026-11-04 探针取证）

用户实机反馈：**左键拖拽变成框选、且看不到笔刷光圈**。反射探针取证后确认——**不是渲染问题，是同一条断链**：

| 证据（探针实测） | 结论 |
|---|---|
| `_instance = NULL(面板未开)`、`CurrentMode = Inspect`，而用户截图面板正在雕刻模式 | 门禁读的 `CityWindow.CurrentMode` 是 `EditorWindow` **静态**字段，域重载后归零且不被窗口布局恢复 |
| `Tools.activeToolType = UnityEditor.MoveTool` | 笔刷未 `evt.Use()` ⇒ 鼠标原样落给默认工具 = 框选（反馈②） |
| `duringSceneGui` 钩子数 = 3，**含** `SculptBrushTool.OnSceneGUI` | 回调注册没问题 ⇒ 是回调第一行就 `return`，光圈代码从未执行（反馈①） |
| `CityTerrain.Delta = NULL`、`FindAssets(t:SculptDeltaAsset) = 0` | 雕刻层**从来没有被创建过**，即便修好门禁，落笔仍会被 `_blocked`（且提示只在控制台） |
| `FindAssets(t:TerrainProfile) = 0` 而该资产**确实存在且有路径** | 内嵌包不入 AssetDatabase 索引 ⇒ 旧代码以"找不到"当"不存在" ⇒ 每次创建实例都新建副本（副本滋生机制，H-52） |

**修复（D-34 / D-35）**：接管权改为 `CityTerrain.SculptToolActive` 序列化字段（跨域重载存活），
笔刷只遍历注册表读它；雕刻层在创建实例与进入 ② 步时自动建并绑；包内资产一律固定路径 + `LoadAssetAtPath`；
光圈高度改从 `CityTerrainView.BoundField` 取（与画面同一张场，不再依赖只有面板驱动分支才有的 `ActiveContext`）。

> 教训（与 H-48 同族）：**"面板显示什么"不等于"数据里是什么"**。M4-h 我把高亮做成由真源回推，
> 却把**门禁**留在编辑器内存里——回推修的是显示一致性，没修可用性。凡是"跨域重载后还能不能用"
> 的问题，先问这个状态存在哪一侧：存在 `EditorWindow` 静态字段里的，一律按会丢处理。

## 1.2 步骤条可用后仍「地表不动 + 每笔读条」的真因（M4-j，2026-11-05 实测）

用户实机反馈：**抬升后地表没有同步变动**、**每次笔刷编辑非常卡（需要读条）**。探针逐句复刻调用组合后实测：

| 证据（实测） | 结论 |
|---|---|
| `_ctx=NULL` 而 `_project` 有值、面板行显示「未装配」 | `_ctx/_runner` 是瞬态字段、域重载即丢 ⇒ 显示层**无声回落到自建路径** |
| 耗时分解 `S1a=4860ms / S0=114ms / S1b≈0ms` | 卡顿不是"算法慢"，是**每笔都在重跑噪声基底**（自建路径无差别 `MarkDirty(DirtyBits.All)`，**违反 D-31/A-2**） |
| 完整重跑 3 轮 **5253 / 5234 / 5529 ms/笔** | 与体感"数秒读条"吻合；另每笔新分配 ctx 两张 400 万格数组（≈40MB）+ 阶段 scratch（≈50MB）⇒ **大对象堆 ⇒ 阻塞 GC** |
| `ComputeConfigKey()` 落笔前后逐位不变（`14071847608170291442`） | 自建路径只认 `cfgChanged` 一条判据、指纹**不含 `_terrain.ManualVersion`** ⇒ **算得出但画不出**（反馈①真根因） |
| 数据侧 `Heights−BaseHeights` 最大正差 **181.11m**（`BaseHeights` 全图最大仅 5.36m） | 雕刻确实进了高度场；画面却一张 mesh 未重建。光圈仍贴山爬动（读的是 `BoundField`），正是"数据活、画面冻"的直观证据 |

**修复（登记 D-36 / D-37）**：

1. **装配自愈**：`_needsFirstBind` + 更新循环"探测到实例才装配"（找不到下一帧再试）；每帧
   `!ReferenceEquals(CityRuntime.ActiveContext, _ctx)` 就重接桥。**禁止在 `OnEnable` 里直接 `Bind`**
   ——此刻场景对象尚未进 `IntentRegistry` ⇒ `SyncStages` 只注册得出 S0 ⇒ 面板已接管、显示层已放弃自建、
   却永远拿不到高度场 ⇒ **画面全白，比修复前更糟**（H-58，我自造后当场纠正）。
2. **自建路径按变化来源分层**：项目变→重建上下文；仅 Profile 变→只重跑 S1a；
   **仅实例版本变（雕刻）→只重放 delta + S1b**；`PipelineContext` 与阶段对象长期复用（消掉每笔 ≈90MB 分配）。
   ⇒ 使 **D-31「雕刻不得脏 S1a」在面板与自建两条路径同时成立**（旧版只在面板侧成立）。
3. **「数据算过」独立成一条重建判据**（`_ownDataChanged`）+ 按笔刷脏盒 `RebuildRegion`；
   **刻意不把实例版本补进 configKey**（补进去 ⇒ `cfgChanged=true` ⇒ `RebuildAll`，实测全量 289ms vs 增量 0~2ms）。
   脏区须由面板 `_ctx.AddDirtyBound(Tracker.LastDirtyBounds)` 显式搬入，且必须在 `ConsumeDirty()` **之后立刻取**
   （该入口会把 `LastDirtyBounds` 复位成 default）。

**同口径实测对比**：每笔重算 **5253ms → 4ms**；执行阶段 **3 → 1**（仅 S1b）；显示重建
`不重建／全量 289ms → 增量 0~2ms`（实测状态串 `增量重建 9/9 chunk（脏盒 202×202m，全图 3969）`）；
每笔新分配 `≈90MB → ≈0`；mesh 顶点 y 范围 `[-7.6,5.3]` 与数据 `[-7.6,5.4]` 吻合 ⇒ **画面已同步**；空转一帧 0ms。

> 方法论留痕（两次）：① **「我推断的代码」≠「用户实际执行的代码」**——第一次只测 `EnsureField`+S1a
> 得 8ms，差点反向得出"卡顿与噪声无关"；逐句复刻调用组合才量到 5.2s。② **断言先红先查自己口径**——
> 我曾用粗粒度入口 `MarkIntent`（并全部通道）断言"雕刻只脏 Flatten"而误判实现有 bug（H-62）。

## 2. 关键发现：坡度退让判定时机**不能放在 S1b**（否则路网已定，退让无意义）

按 `ExecutionOrder`：`S3_Road` 早于 `S4_Parcel` 早于 `S1b_Flatten`。
"太陡不可建、让路网绕行"要求**道路排布时就知道哪里陡不可建**；若在 `S1b`（道路之后）才判陡，
路网早已穿过陡区、退让形同虚设。因此硬退让必须拆成**早判 + 晚用**两处：

```
S1a/S2/sculpt 完成"自然地表" 后 —— 立刻（新增 S_Guard 或 S1a 末尾）：
    steepMask = 逐格 GetSlopeDeg(x,z) ≥ hardRetreatSlope ? NoBuild : 0        ← 纯函数，只依赖已有高度
    写入 CellFlag.NoBuild（词表已存在，AssembleStage 已在用）
S3 路网 读 NoBuild → 绕行陡区
S4 地块 读 NoBuild → 不在陡区切地块
S1b 平整 只对"落在可建区、且中坡"的地块施加压平约束
```

- 判据是"逐格坡度"还是"地块整体坡度"？**两档都要**：`NoBuild` 按逐格（陡到不能修的坡，路也不该硬上）；
  `S1b` 的"中坡压平/轻整理"按地块核心整体（`PlaneFitting` 已有中位数+LSQ，M2 实测 4.79°→1.41°）。
- **代价**：新增一个"地表→坡度掩码"的早判步，是**新的脏传播面**（改噪音/雕刻 → steepMask 变 → S3/S4 脏）。
  须同步三处（§5 勿碰项纪律）：`DirtyBits` 增 `SlopeGuard`？或复用 `Terrain`→下游；`IntentChangePlanner.Next`；`StageClaims` 认领。
  **倾向前者更省**：steepMask 派生自 Terrain，不新增脏位，改 Terrain 已展开 Flatten/Road/Parcel——只需在 `S3_Road`/`S4_Parcel` 的 Run 内**先算 steepMask 再排布**（纯函数、无阶段注册成本）。**待你定。**

## 3. 三级梯度退让的确切语义（替换现有二元"压平/不压平"）

现状（01 §3.5）：拟合坡度 `≤ maxParcelSlope(5°)` 用拟合面，否则**退化为水平面**（即大挖大填、总是压）。
= 二元：要么轻压、要么硬压平，没有"放弃"这一档。

改为三档（新增 1 个 Profile 参数 `hardRetreatSlope`）：

| 地块核心坡度 θ | 处置 | 掩码 | 现有代码 |
|---|---|---|---|
| θ ≤ `maxParcelSlope`（≈5°） | 保留自然坡，**轻整理**（拟合面，几乎不动） | 可建 | `PlaneFitting` 拟合分支（已有） |
| `maxParcelSlope` < θ < `hardRetreatSlope` | **压平**到目标面（M2 的 8x 强约束） | 可建 | `FlattenSolveStage` 融合（已有） |
| θ ≥ `hardRetreatSlope` = **18°（已定）** | **不压**，削掉陡的那部分、保留地块内缓角 | 逐格 `NoBuild`（+可选 `NoRoad`） | **新增** |

`hardRetreatSlope` 进 `TerrainProfile`，面板滑条可拖；与 `maxParcelSlope` 之间留死区（5°→18°）避免边界抖动。

**已定的两个数（用户 2026-11-03）**：
1. `hardRetreatSlope` 默认 **18°**。
2. 陡区处置 = **只削掉陡的那部分、保留地块内缓的一角**（贴近真实山城，代价是地块多边形需按坡度裁剪）。

**"削角保缓"的实现口径（M4 落地时遵守）**：
- 逐格 `NoBuild` 判据是**坡度场**（`GetSlopeDeg ≥ 18°` 的格），与地块形状无关 —— 这一半是纯函数、可单测；
- 地块侧：S4 切出的多边形**不被整块丢弃**，而是保留"非 NoBuild 连通块"作可建子区；
  子区面积低于 03/04 的 `minParcelArea` 才整块作废（避免削完后留下没人要的碎地）；
- 地块目标平面（S1b 拟合）的样本域 = **可建子区内的格**，不是原多边形全境：
  否则陡角的极端高程会把中位数/坡向拉偏，缓角反而被压成歪的（同 01 §3.5 的"残缺多边形对均值敏感"教训）。

**仍未定、但不阻塞实现**：`minParcelArea` 的 03/04 双处配置尚未归一（M1 遗留，本增量不碰）；
"整块作废"阈值就用现有的 `minParcelArea`，不新造参数。

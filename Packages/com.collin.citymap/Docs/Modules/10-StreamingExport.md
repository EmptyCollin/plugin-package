> 依赖：00（格网/管线）、07（落位记录）、08（反悔/人工层）。

> 这两条合起来推翻了 07 原先"建筑 = 场景 GameObject 落盘"的默认，是本包**最大的一次架构调整**。

## 1. 容量核算（先算，不靠感觉）

| 世界 | 逻辑格 | 格数 | 高度场+掩码+用途场（float 口径） | 同项（量化口径） | 显示 mesh 顶点 |
|---|---|---|---|---|---|
| 2km | 2m | 1.0M | 21 MB | 8 MB | 0.1M |
| 4km | 2m | 4.0M | 84 MB | 31 MB | 0.3M |
| **8km** | **2m** | **16.0M** | **336 MB** | 122 MB | 1.0M（显示 8m）|
| **8km** | **4m** | **4.0M** | **84 MB** | **31 MB** | 0.3M（显示 16m）|

**结论 1（H-18）**：8km × 2m 逻辑格 = 16M 格、三场合计 336MB（float32），
叠加 Job 中间缓冲与 GC 抖动，Editor 侧不可接受。**8km 档必须把逻辑格升到 4m**（或 2m + 强制量化，见 §2.3）。
副作用：地块/退让/slot 间距的格表达精度减半 → 所有"以格为单位"的参数**改用米表达**（`ParcelProfile` 已是米，
03 `minSegmentLen` 亦是；仅掩码/采样层受 4m 量化影响，临街判定容差从 ±1 格放宽到 ±2 格）。

**结论 2（H-17，阻断级）**：10 万栋若按 07 v5 原设计落盘成**场景 GameObject + `CityBuildingTag`**，
则场景 YAML 文件将膨胀到数百 MB 量级（10 万个带 8 个序列化字段的组件 + prefab 实例引用），
表现为：打开场景分钟级、保存分钟级、`AssetDatabase` 索引风暴、undo 栈与序列化互相放大——**编辑器实际不可用**。
这不是性能优化问题，是**必须换真源表示**的问题。

## 2. 新架构：数据态真源 + 视口投影

### 2.1 三层划分（替换原"实例落盘"模型）
```
① 意图层（落盘 SO，人工编辑的对象）      不变：河线/骨架路/场域/城心锚点/人工层 delta/锁区/负约束
② 结果数据层（落盘 SO，紧凑二进制）      新：BuildingRecordAsset（10万栋 = ~3.2MB）、Occupied 索引
③ 表现层（内存 GameObject，按需实例化）  新：ViewportRealizer —— 只把工作集内的建筑物化为对象
```
- **建筑的真源是 `BuildingRecord` 数据，不是 GameObject**。GameObject 只是它的临时投影，可随意销毁重建。
- `CityBuildingTag` 降级为**投影上的反向指针**（`recordId`），不再承载持久语义（07 §5 相应改写）。
- 收益：① 打开/保存场景恒定成本（与工作集大小相关、与全图无关）；② 导出三形态直接消费②；
  ③ "运行时生成"成为同一份数据的另一个消费者，不需要重写生成内核。

### 2.2 `BuildingRecord`（紧凑结构，全图常驻）
```csharp
struct BuildingRecord {         // 目标 ≤32 B/栋 → 10万栋 ≈ 3.2 MB
    int   id;                   // 稳定 id（永不复用；由 parcelId+slotIndex+salt 派生，同 03 规则）
    int   rowId;                // → BuildingProfile 行
    uint  packedPos; uint packedPosZ;  // 定点量化（0.01m）
    ushort yawCcq;              // 朝向（1/4 度）
    short  repeatOrScale;       // stretch: 段复制份数；降级: 缩放×100
    byte   flags;               // adopted|userModified|orphan|approximated|locked 位
    byte   landUseDominant;     // 落位时主导维
    ushort thresholdUsed;       // 落位时门槛（0~100，可舍入）
}
```
- **人工改动也记在这里**（`flags.adopted/userModified` + 量化后的 pos/yaw），而不是靠场景组件存活 →
  这是 H-10 认回机制在 8km 下的正解：**认回靠记录，不靠遍历场景**（v5 方案在 10 万栋下同样不可行，见 §4）。
- 记录是**半派生**的：`(rowId, pos, yaw, repeat)` 可由 f(意图层, seed) 重算，但 `flags`/人工改动是意图。
  因此持久化策略 = **默认重算，仅当存在人工改动/adopted 时才落盘这份记录资产**（否则仍守 D-13）。
  落盘时带 `intentVersion` 指纹：版本对得上→直接复用记录（快）；对不上→重算并与旧记录 diff（把变化写回，保留 flags）。

### 2.3 大尺度场数据布局
| 数据 | 8km 档选型 | 说明 |
|---|---|---|
| 高度场 | `int16` 量化（±32767，1cm 精度，量程 ±327m） | 31MB→8MB；地形高程不可能超此量程 |
| 掩码 | `ushort[]`（00 §2.4 已升位） | 8MB |
| 用途场 | 4×`byte`（门槛整数化后 0~100 足够，D-02 本就整数） | **15MB**（原 float 口径 61MB） |
| 分区（region） | `regionSize` 默认 1024m（=8×8 chunk） | 场数据的磁盘/内存加载单位 |
- 用途场用 byte 后，05 §3.1 的过渡带曲线精度从连续降为 1/100 步进 —— 与门槛语义（整数）一致，无损失。
- 场数据**按 region 分块惰性加载**（region 文件 = 裸二进制，`.tmp` 缓存或结果层资产），避免一次性 84MB 常驻。

## 3. 工作集（Workset）：编辑器只面对"一片"

### 3.1 定义
```
工作集 = 视口 AABB ∩ 全图 → 展开到整 region → 再外扩 1 region（邻域上下文）
```
- 默认工作集目标：**≤ 2 个 region、≤ 4096 栋实例化**（256m×256m 见 §1 结论 2 的量级估算，实测约 1300~3000 栋/region）。
- 相机移动 → region 进出 → `Realizer` 物化/回收 GameObject（带 LRU 上限，默认 8 个 region 常驻）。
- **回收只销毁投影，不动记录** → 用户不会丢东西；`userModified` 的编辑在回收前必须已写回记录（保存钩子强制）。

### 3.2 关键语义变更（必须显式，否则反悔体系会静默失效）
| 场景 | 未加载区域的行为 |
|---|---|
| 改 ρ / 改河 / 改表 | **数据层全区重算**（只跑记录，不实例化）；表现层只刷工作集。→ 未加载区不会"没更新" |
| 影响预览 dry-run（08 §6.2） | 必须覆盖**全图**（不能只算工作集），否则"先锁定受影响区域"在最需要它的 8km 场景失效（H-19） |
| 冲突条目（08 §3.4） | 全区生成，列表按 region 折叠显示"未加载区还有 12 条"；点击定位=自动把该区拉进工作集 |
| adopt / 锁区 / 负约束 | 全区可用（作用于数据/意图层），**不要求对象在场景里存在**；面板提供"按记录 id 选择"入口（框选 + 区域选择器） |
| L1 Unity Undo | 只能撤销**工作集内**的对象级改动（记录改动走 IntentJournal/L2）→ 面板 help 明写此边界 |
| L3 区域恢复 / L4 检查点 | 全区可用（快照本就以数据为单位） |
| Ctrl+A 全选建筑 | 默认限工作集；全图操作请走"按区域/按条件批量"面板（防误伤 10 万对象） |

### 3.3 与 §1 结论 1 的关系
4m 逻辑格 + region 分块加载后，8km 档的常驻内存 ≈ 工作集 region 的场数据（约 5MB/region）+ 全区记录 3.2MB + 索引，
**总量 < 40MB**，比 2km/2m 的 v5 设计（21MB）只高一点，但支持了 16 倍面积。

## 4. 认回（reclaim）在 8km 下的改写（修正 v5 的 H-10 裁决）

v5 方案：S6 启动时扫场景所有 `CityBuildingTag` 建 reclaim 表。
**10 万栋下不可行**（`FindObjectsByType` 遍历 10 万对象 ≈ 百 ms~秒级，且多数对象根本未加载）。
新方案：
```
① 读 BuildingRecordAsset（若存在且 intentVersion 匹配）→ 全区记录 = 现状，无需扫场景
② 版本不匹配 → 重算 f(意图层,seed) 得新记录 → 与旧记录按 id diff：
     保留 flags/人工改动位；记录变化集 Δ（新增/删除/位移）
③ 工作集内：按 Δ 物化或回收投影；投影上若发现"比记录新"的人工改动（用户刚在场景挪了对象）
     → 以场景为准写回记录（场景是最近交互现场，冲突方向固定为"场景赢"，并记 journal）
④ 无记录资产（首次/纯派生城）→ 才走 v5 的场景 tag 反查兜底（仅工作集内，成本可控）
```
- **D-08-14 修订**：认回依据从"`CityBuildingTag` 唯一"改为"**记录资产为主，tag 反查为首次兜底**"。
  H-10 的病根（跨会话静默叠楼）由"记录 + intentVersion 指纹"更彻底地解掉，且在 8km 下才成立。
- A-30（认回幂等）证据方式相应更新：断言"重开→保存后记录资产逐字节一致，且工作集投影无净增实例"。

## 5. 导出层：三形态（用户决策 1 落地）

真源统一 = `①意图层 + ②记录数据 + Model 参数`；导出 = 对这份数据的三次投影。

### 5.1 形态 A：Unity scene 切块（`SceneChunks`）

- **切块尺寸 `chunkSizeM` 支持自定义，默认 1024m（用户裁决 Q-12）**，可选 256 / 512 / 1024 / 2048m，
  必须是逻辑格 `cellSize` 的整数倍（非整倍直接拒绝并提示可用值，避免边界格被劈开）。
  一个块 = 一个 `.unity`，`Additive` 加载，块间用 `ChunkManifest.json` 串联（记块尺寸、块数、坐标原点、各块文件名与包围盒）。
- **切块边界与 region 边界是两个正交概念**（不可混用）：
  `region`（1024m）= **编辑期工作集/流式单位**（10 §3，决定实例物化与卸载）；
  `scene chunk` = **交付期单位**（决定磁盘上有几个 `.unity`）。默认值下二者恰好重合纯属巧合，
  改 `chunkSizeM` 只影响导出产物，不改工作集行为（反之亦然）。
- **H-25（本轮新发现）：`chunkSizeM < region` 时的地形 mesh 归属**。若沿用"每块自带 region 的显示 mesh"，
  一个 256m 块的地形会来自 4 个 region 的 mesh 拼接，接缝与烘焙一致性都要额外处理。裁决：
  **导出地形一律按切块边界独立重切 mesh**（从高度场直接采样，不复用 region 的视口 mesh），
  代价是导出时多一次 mesh 生成（可分帧、可取消），换来"交付块与编辑工作集完全解耦"。
  `chunkSizeM ≥ region` 时退化为按 region 切，无额外开销。
- 跨块对象归属：**按包围盒中心**落入唯一块（默认不复制、不裁断）；
  面板在切块边界画参考线（随 `chunkSizeM` 实时变），导出报告列出"包围盒中心贴近边界 ±2m 的对象清单"，
  由用户决定是否挪动——避免"贴着边界被切走"后两边各缺一半。
- 长条对象（河线、pinned 主干路）跨多块：整条归属中心所在块，**其余块内不出现**（不是裁断）。
  因此 8km 下一条横贯全城的主干路只会存在于一个块。导出报告显式提示该现象，
  并提供 `splitLongStrokes`（默认关）：开启后按块裁断 + 端点接续标记，供需要"每块可独立运行"的交付场景使用。
- Model 依赖：`TerrainProfile`/`BuildingProfile` 等以引用进入包，或可选"烘焙进块内子资产"（脱包交付时避免缺依赖）。
- 产物落 `Builds/Export/`（AGENTS §9 已忽略，不入库）。

### 5.2 形态 B：格式化数据（`CityData`，引擎无关）
- 格式：**JSON（可读、可 diff）+ 可选二进制 tile（大图性能）**，schema 版本化，**不含任何 Unity 类型名**。
```
citydata.json = { schema:"citymap/1", region:{sizeM, extent}, grid:{cellSize:4, origin},
  terrain:{ encoding:"int16|png16", heightScale },
  roads:{ nodes:[id,x,z,kind], edges:[id,a,b,grade,width] },        // 仅中心线+等级，不做车道几何
  parcels:[ {id, ring:[[x,z]…], landUse:[f,i,r,a], dominant} ],
  buildings:[ {id, x,z, yawDeg, rowId, footprintW/D, height, stretchable, repeat} ],
  fields:[ {id,type,x,z,innerR,outerR,innerValue,outerValue,curve:[knots],enabled} ],  // 意图原样带出
  water:[ {strokeId, polyline, width, order} ],
  prefabs:[ {rowId, path, guid?} ]                                   // 资产依赖清单（不含资产本体）
}
```
- `prefabs[]` 是**路径清单而非资产**：非 Unity 引擎消费时由对方自行映射（导出报告列出无法解析的路径）。
- 与 AGENTS §6 的"部分提取"是两件事：§6 指**插件包**导出 unitypackage；本节指**城市产物**导出。文档与菜单命名必须区分
  （菜单：`Collin/CityMap/Export City Data…` vs 工具包提取另立）。

### 5.3 形态 C：2D tile（栅格，用户提到"甚至可能转化为 2D 的 tile"）
- 分辨率独立参数 `tileCellSize`（默认 4m，可选 1/2/4/8m），与逻辑格解耦（可上采样/下采样）。
- 通道分配（可组合导出，每种单张 PNG16/PNG8）：
  | 图层 | 内容 |
  |---|---|
  | `height` | int16 PNG（灰度 16bit），带 scale/offset 元数据 |
  | `mask` | 位平面合成（可建/水/水缓冲/路/占用/禁建…），PNG8 或逐位单通道 |
  | `landuse` | 4 通道（F/I/R/A，byte）或 argmax 索引图（PNG8 + 调色板映射表） |
  | `roads` | 中心线索引图（PNG16，像素→edgeId）+ 边表 JSON |
  | `buildings` | footprint 索引图（像素→buildingId）+ 记录表 |
  | `combined` | 目视用 RGB（同 05 §4.3 合成视图配色，便于人眼核对） |
- **2D/3D 一致性断言**：同一 `citydata` 与 tile 导出必须互推一致（tile→记录 能还原 id 归属），
  这是防止"两套导出各写一半逻辑"的验收抓手（A-40）。
- **Q-11 裁决（用户）：对接时补适配器**。本节通道方案即本包的**基准格式（canonical）**，不猜任何外部瓦片规范：
  1. 基准格式**先行实现并冻结**（M11），它同时是 A-40 往返一致性的被测对象；
  2. 外部规范（Tiled/LDtk/自研 tileset 的尺寸、编码、图层命名、工程文件）出现时，**只在 `ExportAdapter` 层做映射**，
     禁止改动基准通道的语义与编号；适配器是纯投影、不得反写记录；
  3. 每个适配器必须自带一份"基准 ↔ 外部"字段对照表与一条往返用例（外部格式解析回索引图 → 与基准逐像素比对），
     否则不合并（防"加了个导出按钮但没人知道它丢了什么"）；
  4. 因外部规范未知，**不阻塞 M11**：内部格式独立可验收，接入成本显式记为一次返工（Q-11 的已知代价）。
- 不做的事：不生成美术贴图（色块/索引而已）、不为想象中的外部规范预留字段。

### 5.4 导出的正确性前置（H-20/H-21/H-22）
| 编号 | 问题 | 裁决 |
|---|---|---|
| **H-20** | 导出时派生层与工作集耦合（未加载区的记录可能落后） | 导出前强制 **`EnsureWholeMapConsistent()`**：全区重算记录（不实例化，纯数据），完成才允许写文件；面板显示进度（8km 全区记录重算预算 ≤90s，见总纲 §8） |
| **H-21** | error/warning 条目未清零就导出 → 把已知坏成果发出去 | 沿用 08 门禁：**有 error 阻断导出**，warning 需用户在导出对话框勾选"已知并接受"；info 不阻断 |
| **H-22** | 三形态各自演化（导出代码三份、语义分叉） | 单一 `CitySnapshot`（全图只读快照）作为唯一上游，三形态都是它的消费者；禁止形态 A 直接读运行时对象 |

## 6. M9 延后（用户决策 2：批准 ADR-0001 但等 M9 一起做）的后果与处置

- **M8~M9 期间全程走降级路径**（`Transform` 等比缩放）：功能不受阻，但 A-6-6/A-13/A-9b 的验收在 M8 只能测降级态。
- **H-23（后果，必须处理）**：切到 stretch 后，同一目标高度的几何**与等比缩放不同**（分段复制保持窗户比例，缩放会拉长）。
  若不追溯，M9 之后老建筑的视觉会与新生成的不一致（同一栋楼两种"高法"）。
  裁决：
  1. 记录里 `repeatOrScale` 的语义由 `flags.approximated` 明确区分，两者互斥；
  2. 提供一次性迁移动作「重建降级建筑高度」= 对 `approximated=true` 的记录逐个 `TryBind+SetRepeat`，
     走 08 §5.2 journal（可整条撤销），完成后 `approximated` 清零；
  3. 面板在 M9 前后都显示"降级建筑 N 栋"，N>0 时导出报告写明"其中 N 栋为等比缩放几何"（H-21 的 warning 级）。
- ADR-0001 的**签名冻结时点**改为 M9 起点（而非 M0），但接口草案与批量成员保留在 06 §4.2（实现顺序：先接口，后注册）。

## 7. 模块内决策
| 编号 | 决策 | 备选 | 理由 |
|---|---|---|---|
| D-10-1 | 建筑真源改为 `BuildingRecord` 数据层，GameObject 降为视口投影 | 维持场景实例落盘（v5） | 10 万栋的 YAML 场景不可用（H-17）；同时让"运行时生成"与"数据/tile 导出"零重写 |
| D-10-2 | 8km 档逻辑格 4m + `int16` 高度 + `byte` 用途场 | 2m float | 16M 格 float 口径 336MB，Editor 不可接受（H-18，§1 实算） |
| D-10-3 | 工作集 = region(1024m) ± 1，常驻 ≤8 region；场数据按 region 惰性加载 | 全图常驻 | 常驻内存 <40MB 且打开成本恒定（§3.3） |
| D-10-4 | 全区数据重算与工作集解耦（dry-run/记录全图，实例化仅工作集） | 只算工作集 | 否则影响预览/冲突检测在未加载区失明（H-19），且导出会带脏数据（H-20） |
| D-10-5 | 认回主依据 = 记录资产 + `intentVersion` 指纹；tag 反查退为首次兜底 | v5 的 tag 唯一依据 | 10 万对象遍历不可行（§4），且记录方案更彻底地解掉 H-10 |
| D-10-6 | 三形态共享单一 `CitySnapshot`（全图只读快照） | 各形态独立导出 | 防止语义分叉（H-22）；快照即 H-20 一致性检查的产物 |
| D-10-7 | `chunkSizeM` **可自定义（默认 1024m）**，须为 `cellSize` 整数倍；与 region 概念正交；地形按切块边界独立重切 mesh | 写死按 region 切 | Q-12 用户要求可配；写死会把"交付单位"与"工作集单位"绑死，改一处牵全身（H-25） |
| D-10-8 | `citydata.json` 不含 Unity 类型、`prefabs[]` 只给路径清单 | 直接序列化 Unity 对象/打包资产 | 用户明说要给外部/2D 消费；资产本体属交付方职责，不猜格式 |
| D-10-9 | M9 后提供「重建降级建筑高度」一次性迁移，`approximated` 与 `repeat` 互斥 | 让降级几何永久留存 | 同表同参数不得有两种高度语义（H-23） |

## 9. 风险
- **H-24：把"数据态"做成功能做不全**（首次成文时误写为 H-44，已订正）——最坏结果是视口投影与记录长期不一致。缓解：`Realizer` 只做"记录→对象"单向物化，
  任何"对象→记录"的写入只允许来自保存钩子与显式编辑命令（两处入口，可审计）。
- **H-25（Q-12 落地时新发现）：切块尺寸改成可配后，地形 mesh 与长条对象的跨块归属未定义**。
  `chunkSizeM < region` 会让一块地形来自多个 region 的 mesh 拼接；横贯全城的河线/主干路会整条消失在其他块。
  处置见 §5.1（导出按切块边界独立重切 mesh + 导出报告列边界对象清单 + `splitLongStrokes` 可选裁断）。
  教训与前三轮同类：**把写死的值改成可配，不是加一个参数，而是必须重新回答它原先隐式承担的全部归属规则**。
- 定点量化（0.01m）与 `int16` 高度使"绝对逐位一致"（A-1）改为"量化后一致"；断言口径统一为 **≤0.01m / ≤1 量化步**。
- region 边界的场数据接缝（用途场/高度场跨 region 采样）需要 1 个 region 的重叠读取（halo），否则边界地块属性跳变。
- 10 万栋记录的重算即使是纯数据也要数十秒：全区重算必须可取消、分帧，且**默认只在导出/显式重生成时做**，编辑期绝不做。
- 2D tile 的具体规范仍未定（用户仅说"甚至可能"）：本设计给的是内部一致的通道方案；若对接具体外部瓦片体系，
  需另取规格并可能新增 `ExportAdapter`（属新需求，非本包默认范围）。

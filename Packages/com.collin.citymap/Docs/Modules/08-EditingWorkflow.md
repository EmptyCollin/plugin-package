# Modules/08 — 编辑管线：操作顺序、反悔体系与局部回滚

> 依赖：横切 00~07（本模块定义"用户怎么按顺序用这套工具、以及如何撤销任何一步"）。
> 对应里程碑：M1（journal 骨架）→ 各工具落地时挂接 → M8（冲突/预览）→ M10（历史面板）。
> 状态：草案。**这是总纲 v2 缺失的最上层设计，评审时优先看这份。**

---

## 1. 问题定义

三个此前没有成文回答的问题：
1. **顺序**：地形/河流/路网/场域/建筑互相依赖，用户按什么次序编辑与生成？上游改了下游怎么办？
2. **反悔**：这个工具里"撤销"一词至少对应四种不同对象（一次拖动、一次参数改动、一次整城重算、一周前的版本），各怎么撤？
3. **局部反悔**：改 ρ 后只想退回 A 区、删掉一条自动生成的路、把某街区恢复成上次结果——这些"只反悔一块"的操作怎么表达？

## 2. 统一模型：一切反悔 = 操作意图层

**基础等式**（本模块第一原理，D-08-1）：

```
地图状态 = f( 意图层 , seed ) ，  意图层 = Model参数 ⊎ 人工层对象
派生层（地形基底/自动路网/地块/slot/用途场/建筑实例/mesh）是 f 的输出，本身不可"撤销"，只会随意图层重算。
```

由此得到三条纪律：

| # | 纪律 | 后果 |
|---|---|---|
| R-A | **反悔 = 把意图层改回去**，派生层自动跟上 | 撤销永远不需要"恢复几千个 GameObject"，只恢复几十~几百个意图对象 |
| R-B | 意图层变化 → `manualVersion++` → `UndoHistoryTracker` 感知 → 最小脏集合重算 | Unity 原生 undo 与自动跟随天然一致（见 §5.1） |
| R-C | 想反悔的对象若**不在意图层**（= 纯派生物），必须先把"不想要它"表达成意图（负约束），或把"想要它"表达成意图（adopt/锁区） | 见 §4，这是"局部反悔"的两个正解，没有第三种 |

R-C 值得展开：**派生物没有"撤销"，只有"约束"**。删掉一条自动路然后重生成，它会原样长回来——不是 bug，
是确定性管线（00 §3.3）的必然。所以"删自动物"的正确语义是"生成一条让它不再出现的负约束"（§4.3）。

## 3. 推荐操作顺序（建议，不阻塞）

### 3.1 三阶段九步（自上而下，Route 1）
```
阶段A 定意图 —— 建立"人工层骨架"，此阶段产物全部是要长期保留的
  A1 新建城：seed + 世界尺寸 + urbanFlatness           → S0,S1a
  A2 放场域：CBD/工业带/农业环（意图的总纲）            → S5 预览
  A3 画河：主干笔画                                    → S2
  A4 点主干路网：Highway/Arterial/Collector 骨架        → S3 人工层
阶段B 定规则 —— 预算与表，此阶段全部是参数滑杆
  B5 ρ 补全支路（滑杆实时生长）                        → S3 自动层
  B6 地块参数微调（退让/进深/覆盖率）                   → S4
  B7 建筑表就位（拖 prefab、四维度、stretchable）        → 06
阶段C 出结果 —— 生成与修订
  C8 全城填充（自动跟随下其实已实时发生，此处=精算 Commit） → S6
  C9 局部修订：手刷/adopt/删除/锁区/场域微调              → 局部 S5,S6
  C10 检查点快照 + 交付导出
```
主面板顶部给一张**可关闭的九步 checklist**（首次使用自动展开，完成打勾，随时可点回跳）。

### 3.2 自下而上（Route 2）："先看一眼再改"
`[一键造城]` = 用当前默认参数直接跑 S0~S6 → 用户站在成品上改。
两条路线**共用同一套数据与工具**，不需要任何额外支持：Route 2 的"改"从 C9 进入，
需要动骨架时（重画河、重放场域）直接回到 A 阶段工具即可——人工层对象不分先后，改哪个就脏哪条依赖链。

### 3.3 为什么不阻塞顺序
- 任何阶段工具在任何时刻可用（面板只报告各阶段状态，不禁用工具）。理由：Route 2 与"改到一半回头"是常态，
  强制顺序的表单向导在创作型工具里是灾难。
- 阶段状态机（唯一需要"顺序感"的地方）呈现为**信息而非门禁**：
  `未生成 ｜ 已过期(上游变了，显示影响范围) ｜ 生成中(进度/取消) ｜ 最新 ｜ 部分锁定(N/M 块)`
- `自动跟随=on` 时不存在"过期"（脏即重算）；`off` 时过期阶段黄标 + 提示"有 N 项未生效"（00 A-0-5）。
- **A2 场域先于 A3/A4 的建议**：放完场域后按需用「设为城心」显式提交锚点（01 §4.4，H-7），
  先定城心再画河画路，地形压平与可达性会跟手；反过来也合法，只是 A1/A3/A4 的产物会因锚点变更触发一次近全链重算（高危，过 §6.2）。
  checklist 中把这条写成提示，不写成限制。

### 3.4 上游改动 × 下游状态的冲突矩阵（核心交付物）

| 上游 Commit 操作 ↓ ＼ 下游对象状态 → | 纯自动 | adopted/固化（含 orphan） | 锁区内 | 人工层本体（笔画/pinned/场域/城心锚点） |
|---|---|---|---|---|
| 改 seed / 世界尺寸 | 全量重算（意图层不变→产物全新，**先弹影响预览**§6.2） | 保留；几何冲突→条目 | 不重算 | 保留；越界→条目 |
| 改噪声参数（S1a） | 重算 | 建筑地坪校正（±0.6m 内自动，超出→条目） | 不重算 | 不依赖，无冲突 |
| 改河流笔画 | 受影响水系/地块/建筑重排；**河道遇 `OccupiedHard` 格→改道或条目，不穿固化物**（H-2） | 同左：保留+条目 | 河改道穿锁区→**条目**（锁区边界=不可穿越墙，河被拒） | 人工河线互斥→编辑即改真源，无冲突 |
| 改 ρ / 画路删路 | 自动层增量重算（弹栈/新增；墙变则栈重建，03 H-1）；**细分禁入 `OccupiedHard/NoRoad`** | 固化路=墙，自动路绕行；**固化建筑 footprint 同样=墙**（H-2） | 不重算，边界墙参与细分 | pinned 边永不动（03 §4.4） |
| 拖场域 / 改曲线 | 脏环内用途与建筑重排（S5,S6 局部；**不触发 S1a**，H-7） | 锁区建筑不动；门槛变化致固化楼"形态滞后"→ **info 条目**（H-6） | 不重算 | — |
| 改建筑表 | 脏 parcel 重排 | **删行/引用失效 → 已放实例转 `orphan` 保留**（H-15，非"仅记条目"）：进 `OccupiedHard`、info 条目三选一（删除/保留为固化/改绑指定行）；不自动删物体 | 不重算 | — |
| **删除 pinned 人工层对象**（河段/骨架边/场域） | 其让出的空间参与重排（地块可合并） | **slot 失效的固化建筑 → orphan**（保留 Transform，仍占位，info 条目三选一处置，H-4） | 区内对象不变 | — |
| 城心锚点变更（「设为城心」） | S1a→S1b→S3(纵坡/桥)→S4→S5→S6 **近全链**（=高危，必过 §6.2+自动快照） | 保留；地坪超出容差→条目 | 不重算 | 锚点本身是意图对象 |

**总原则：自动流程永不删除/移动"固化及以上"的对象；做不到的事变成待裁决条目，让用户裁决**（D-08-4）。
条目分三级（H-6/H-4 修订）：**error**（几何违规：重叠/越红线，阻断导出）｜**warning**（掏空、无法收敛等生成质量问题）｜
**info**（形态滞后、orphan 待处置——不打断、不阻断，历史面板可见可一键处理）。
冲突条目 UI：主面板徽章（按级别配色）+ 列表（原因/位置/点击定位/四选一裁决：删固化物｜回滚上游(journal/快照)｜扩大锁区｜手动挪位）。
error/warning 未清零前**阻断交付导出**；info 仅记入 ACCEPTANCE 备注不阻断。

### 3.5 `重新生成` 与 `新建城` 是两个动作，禁止合并（Modules/09 H-16）
R1 期间 00 写「新建城」、01 写「重生成」，Route2 上线后用户会把它们按成同一个按钮——但两者后果相反：

| 动作 | 语义 | 人工层命运 | 确认强度 |
|---|---|---|---|
| **重新生成 Rebuild** | 用**当前意图层**重算全部派生层（换 seed 时只换随机源） | **原样叠回，一条不丢**（A-7/D-08 的落点） | 无需确认 |
| **新建城 New City** | 建立**新的空意图层**（或清空当前）从零开始 | **将被丢弃**：河 N 条 / 固化 M 栋 / 锁区 K 块 | 高危四重：影响预览（列出将丢弃清单）→ 自动快照 → 二次确认 → **键入确认词**（如城名）|

- 主面板两按钮**分列不同区**（New 在左上"项目"组，Rebuild 在阶段工具栏），文案不共用"生成"一词。
- `New City` 之前永远先落 L4 自动快照（A-25 的触发清单加入本项）。
- Route2 特别提示（H-14）：`一键造城` 完成后显示非阻断 info
  「本次生成 N 栋建筑、M 条路，当前 **0 个固化对象**——后续改动将自由重排全城。 [冻结全城]」，
  `冻结全城` = 一次性 `LockRegion(全图)`（§4.4 口诀表对应行）。造完城就想改细节的用户，这条是唯一能救回"我以为城已经定了"的入口。

## 4. 三种"表达反悔"的意图机制

### 4.1 adopt（固化）：把想要的自动结果变成人工层
- 对象级：右键建筑/路段/水道自动段 → `固化`（03/07 已定义，`adopted=true`）。
- 区域级：即 §4.2 的锁区（批量 adopt）。
- 语义：adopt 前"结果=f(意图)"；adopt 后"结果=f(意图∪{这个东西本身})"。
- **完整语义（Modules/09 H-2 修订）**：adopt 不只是"不再被重排"，**其 footprint 必须烘焙进 `OccupiedHard` 掩码**，
  成为 S2 河道、S3 细分、S6 落位的**硬禁入墙**。否则会出现"自动新路从两栋已固化建筑中间穿过去"
  ——固化物被毁是本工具最恶性的 bug，这条是结构性防线（对应 08 A-19b）。

### 4.2 锁区（LockRegion）：局部反悔的主机制
```csharp
struct LockRegion { string id; Bounds bounds(或 polygon);
    int snapshotVersion;          // 锁定时依据的意图版本号
    List<int> frozenRoadEdgeIds;  // 区内自动路 → 转 adopted
    List<int> frozenBuildingSlotIds; }
```
行为定义（回答"锁了之后世界怎么变"）：
1. **区内**：自动路边批量 adopt、建筑实例 adopt（`userModified` 不强制置位）；地块细分跳过区内；S5/S6 不再重排区内。
2. **边界**：锁区外接框自动生成 **boundary wall**（派生层的隐形墙边，`grade=Wall`，进 03 的不可穿越集合、
   进 02 的河改道判定、不进红线掩码——不是路，只是墙）。
3. **区外**：照常重算；临锁区的细分把墙当已有边处理（端点可吸附到墙，形成 T 口——城市里街区边界本就如此）。
4. **解锁**：`Unlock` = 丢弃这批 frozen 对象（adopted 对象若本身是人工手刷的则保留），区内回到纯自动 + 立即重算。
   解锁前弹确认列出"将丢弃 N 栋、M 条路"。
锁的粒度默认 chunk 网格对齐（128m），支持矩形框选任意范围（内部按 chunk 取整显示）。

### 4.3 负约束（ConstraintAsset）：让"不想要"成为可持久的意图
```csharp
struct NoRoad  { bounds/polyline+buffer }   // 细分与自动路禁入（S3 检查）
struct NoBuild { bounds/poly }              // 掩码位，S4 不产 slot、S6 跳过（与 04 Reserve 同族，语义相反：Reserve=留白给未来，NoBuild=明确不要）
struct NoWater { bounds }                   // S2 自动支流/补下游禁入
```
**联动规则（关键交互决策 D-08-5）**：
- 删除**人工层对象** = 真删除（意图本身没了，Ctrl+Z 找回）。
- 删除**自动对象**（选中 Del）= 自动转为"添加一条覆盖其 footprint 的负约束"，toast 说明
  「已加入禁建/禁路区——重生成不会再长出它；Ctrl+Z 移除该约束」。**不弹窗**（逐次询问打断心流），但约束进面板清单可管理。
- **删自动路时的内联三选一（Modules/09 H-5 修订）**：光挂 `NoRoad` 会让原路址变可建，重生成后**原地长出建筑**，
  与"我要那块院子"的直觉冲突。故 toast 提供内联选项：`[仅禁路（默认）] [禁路且留白（+NoBuild）] [转为人工路（adopt）]`；
  选择结果记进 journal，可整条撤销、可在负约束面板改判。默认仍是"仅禁路"，但后果必须在 toast 里说明白。
- 删除**adopted 对象** = 真删除 + 该 slot 自动挂负约束（否则重生成会在原地长回一个新的，用户会觉得删了个假）。
- 负约束也是意图层：参与 journal、区域回滚、快照、冲突矩阵（上游改动与负约束冲突=条目）。

### 4.4 三种机制的选择口诀（写进面板帮助）
| 想要 | 用 |
|---|---|
| 保住现有结果，以后重算别动这块 | 锁区 |
| **保住整城现状再继续改**（Route2 造完城典型） | **冻结全城** = `LockRegion(全图)`，面板一键（H-14）|
| 这一条/这一栋我确认了，长期保留 | adopt |
| 这里永远不要长出这种东西 | 删除（自动物→负约束）/负约束 |
| 整体退回上次/昨天 | 快照恢复（整城或区域） |
| 这一栋/这一条别再自动变 | adopt 该对象（比锁区轻，不冻周边细分） |

## 5. 反悔体系分层：L1~L4

| 层 | 反悔对象 | 机制 | 范围 | 持久性 |
|---|---|---|---|---|
| **L1 对象级** | 一次拖动/一笔刷/一行表改动/一次场域手柄 | Unity Undo/Redo（动作合并纪律见各模块：一笔画=1 记录，批量=1 记录） | 单次交互 | 会话内（引擎栈） |
| **L2 动作级** | 一次批量意图操作（批量 adopt、锁区、清空建筑、批量删场域） | **IntentJournal**（意图 diff 环形日志）回放 | 单动作 | 会话内 + 可选导出 |
| **L3 区域级** | "这块从头来过" | 区域回滚：区内意图对象↔快照差集恢复，或区内人工层清空回纯自动 | 矩形/多边形 | 依赖 L4 |
| **L4 工程级** | 回到里程碑/昨天 | **Checkpoint 快照**保存/恢复（整城） | 全城 | 资产，入 git |

### 5.1 L1 与派生层的一致性：`UndoHistoryTracker`（本模块最重要的实现件）
Unity undo 只回滚了意图层对象，**派生层还停在 undo 前**（建筑还站在撤销前的路上）。解法（R-B 落地）：
```
每个意图层提交点（Commit/undo/redo 前后）bump 所属对象的 manualVersion；
Tracker 在 EditorApplication.update 里比对两件事（Modules/09 H-9 修订）：
  ① 意图对象集合哈希（对象 id 全集 + 各类计数）  ← 捕捉 undo"恢复被删对象"（其版本可能等于记忆值，仅版本差会漏检）
  ② 逐对象 manualVersion 差                      ← 捕捉参数改动
差异 → 按对象类型映射脏位与 bounds → ctx.MarkDirty(...) → 自动跟随管线重算。
```
**首帧基线规则（Modules/09 H-10b）**：会话/域重载后的第一帧，Tracker **只建立基线、不触发重算**
（否则场景加载会把全部对象判为差异 → 近全量重算）。基线 = 加载完成时各意图对象的（集合哈希 + 逐对象版本）。
此后仅在"集合哈希变化 或 版本差非空"时标脏；场景加载与认回（07 §3.3）本身不算用户编辑。
**对象类型 × 变化 → 脏集合映射表**（Tracker 的唯一规则表，实现时照抄）：

| 意图对象 | 变化 | 脏位 | bounds |
|---|---|---|---|
| 场域 | 移动/半径/值/曲线/类型 | Field→S5,S6 | 新旧外径并集 |
| 场域 | 删除/恢复 | 同上 | 外径 |
| 河笔画 | 任意 | River→S2,S1b,S3(桥),S4,S5,S6 | 线缓冲+外扩 |
| pinned 边/节点 | 增删改 | Road(栈失效重建,03 H-1)→S3,S4,S5,S6 | 边+受影响区域 |
| ρ/预算参数 | 改值 | Budget→S3,S4,S5,S6 | 全图（增量弹栈） |
| 表行 | 增删改值 | Profile→S6 | 脏 parcel |
| adopt/手刷/锁区/负约束 | 增删 | **Occupied 重烘焙**→S2,S3,S4,S6 禁入判定 | footprint |
| adopted 建筑 Transform | 挪动 | **仅 OccupiedHard 重烘焙**（旧+新 footprint）→S3,S6 冲突复检 | 两 footprint |
| 城心锚点 | 提交 | Terrain→S1a..S6 近全链（高危，过 §6.2） | 全图 |

- 即：**undo/redo 在编辑器里被当作一次普通的意图修改**，复用全部脏传播/Preview/Commit 机制，
  不需要任何"撤销专用"的派生层恢复代码（复杂度砍掉一大部分）。
- 性能：集合哈希 O(意图对象数)（千级，亚 ms）；重算走既有最小脏集合。
- 风险：undo 掉一个场域后 S5/S6 重排可能要几百 ms，用户连按 Ctrl+Z 时会排队重算 → Tracker 做 250ms 合并窗口
  （连续 undo 只在停下后重算一次，期间显示"等待历史稳定…"）。

### 5.2 IntentJournal（L2）
```
每条 = { entryId, time, kind(批量编辑|adopt|锁区|负约束|清空|工具首用), 
         intentsBefore:[对象快照(仅被改对象)], affectedBounds, newVersion }
环形缓冲默认 64 条；内存 + 会话结束前可导出 .tmp-inspect/journal.json
回滚动作 = "Revert entry #k..#current"（恢复对象集合 → 版本 bump → Tracker 重算）
```
- journal **只记意图层**，不记派生物（体积=几十 KB/条量级）。
- "撤销一次全城填充"不属于 L2（填充不改意图）→ 用 `清空建筑` 动作（它本身入 journal，可再撤销）。

### 5.3 Checkpoint（L4）与区域恢复（L3）
```csharp
CityCheckpoint (SO) { version; capturedAtUtc; note;
    ModelBlob（7 个 SO 的值序列化，不含资产引用外的东西）;
    IntentBlob（河笔画/骨架图/场域全参数/负约束/adopted 清单/manualDelta 全量）;
    // 派生层不进快照——可重算（D-13）。体积=人工层大小，典型 <2MB }
```
- **显式检查点**：面板「存一版」→ 用户命名 → `.asset` 入库。恢复=覆盖意图层 → 全量重算 → L4。
- **自动快照**：高危操作（seed 改动、全量重生成、恢复检查点、清空建筑）执行前自动存环形快照（默认保留 8 份，
  存 `Library/CitymapAutosnap/`，**不入库**）；面板"历史"页可预览任意自动快照的意图统计。
- **区域恢复（L3）**：选区 → "恢复到检查点 X / 回到纯自动"：
  - 与快照比对，落在选区内的意图对象变更 = 恢复对象；
  - **跨界对象不自动处理**：穿过选区边界的河线/道路边/场域被单独列出，人工裁决"整体回滚 / 保留现状"
    （对折线做裁剪会撕裂真源，明确不做，D-08-7）。
- 恢复动作本身是一条 journal + 一次版本 bump → 可再反悔（反悔的反悔 = 回到恢复前，天然成立）。

## 6. 交互：历史面板与影响预览

### 6.1 历史面板（主面板第 4 页签 `History`）
```
┌ 时间线（意图事件流）：每步图标=操作种类，展开=affectedBounds/对象计数/journal 条号 [回滚到此步]
┌ 检查点列表：命名快照 + 自动快照（灰），[恢复][恢复区域…][删除]
┌ 锁区管理器：列表(面积/冻结对象数/版本) [解锁][扩大][查看边界墙]
├ 负约束管理器：列表(种类/footprint/来源=删除自动物时注明) [移除][临时禁用]
└ 冲突条目：红/黄列表 [定位][裁决四选一][忽略并记录]
```
时间线只显意图事件（用户心智与 L1/L2 对齐）；派生重算不显示为事件，避免噪音。

### 6.2 影响预览（dry-run，事前反悔）
触发条件（满足任一才弹窗，防打扰）：
- 预估波及 adopted/锁区对象 > 0；
- 或波及自动建筑 > 200 栋；或操作 = seed/尺寸/恢复快照/清空；
- **或删除 pinned 人工层对象**（骨架边/河段/场域）——爆炸半径大且必产 orphan 清单，必须预告（H-4）；
- **或城心锚点变更**（「设为城心」）——它触发 S1a→S6 近全链（H-7），是全工具最贵的单步操作。
Dry-run 内容（不生成几何，只跑依赖传播计数，预算 <300ms）：
「本次改动将重算 N 个地块 / M 栋自动建筑；K 个固化对象可能冲突（列出前 10 + 位置）；
 P 栋固化建筑将失去宿主 slot（变 orphan，逐条列出）。 [继续] [先锁定受影响区域] [取消]」
`先锁定` = 对将受波及的 adopted 邻域自动执行 LockRegion 再提交（一键把"事后冲突"转"事前保全"）。

### 6.3 键盘/鼠标总表（与既有模块一致，此处汇总为契约）
| 键 | 全局 |
|---|---|
| Ctrl+Z / Ctrl+Y | L1 撤销/重做（经 Tracker 自动联动派生层） |
| Ctrl+S | 存检查点（弹命名） |
| `L` | 框选锁区（当前工具叠加模式） |
| `Del` | 删除（自动物→负约束规则 §4.3；人工物→真删除） |
| Ctrl+D（选中自动物） | 就地 adopt |
| Alt+拖动场域/节点 | 复制（重发 stableId） |
| Esc | 取消当前工具草稿 / 取消生成 |

### 6.4 工作集（8km/10万栋档）对反悔体系的语义边界（v6 新增，D-25/D-26）
大尺度下场景内只有**工作集投影**（10 §3），部分反悔能力的适用范围随之变化，必须显式写清（否则用户以为"撤销没生效"）：

| 机制 | 全区可用？ | 说明 |
|---|---|---|
| L1 Unity Undo（对象级） | **仅工作集内** | 未加载区没有对象可撤销；该区改动请走 L2/L3 |
| L2 IntentJournal | ✅ 全区 | 负约束/锁区/adopt/批量参数都以记录形式存在，与投影无关 |
| L3 区域恢复 / L4 检查点 | ✅ 全区 | 快照本就以数据（region/记录）为单位，天然适配 |
| adopt / 锁区 / 负约束 | ✅ 全区 | **不要求对象在场景里存在**；面板提供"按记录 id / 按区域 / 按条件"选择入口 |
| 影响预览 dry-run | ✅ 必须全区 | 若只算工作集，"先锁定受影响区域"恰好在最需要它的 8km 场景失效（10 H-19） |
| 冲突条目 | ✅ 全区生成 | 未加载区条目按 region 折叠显示；点击定位 = 自动把该区拉入工作集 |
| Ctrl+A 全选建筑 | **默认限工作集** | 全图操作须走"按区域/条件批量"，防止一次性操作 10 万对象 |

- 面板 `History` 页顶部常驻显示当前工作集范围（如 `工作集：region (3,2)±1，1,842 栋已物化 / 全图 96,310 栋`）。
- 投影回收≠数据丢失：回收前保存钩子强制把 `userModified` 写回记录（10 §3.1）；若写回失败必须阻断回收并报错。

## 7. 反悔链走查（三条真实场景，验收脚本原型）

**S-1 "ρ 拉高了，A 区退回原来的路网，B 区保持"**
B 区若含自动物：无历史可退（自动物本就不持久）→ 正确姿势=当时先锁 A。若用户忘了：
恢复最近**自动快照**中 A 区 → L3 区域恢复（A 区意图对象回滚，B 区保持当前）→ 冲突仅发生在跨界边（列出让用户裁决）。
文档结论：checklist C9 步的提示文案直接写"先锁区，再动全局参数"；影响预览是防呆第二道。

**S-2 "自动生成一条路穿了我看中的临河地块，删掉它"**
`Del` → 自动挂 `NoRoad(走廊)` → 重生成不再出现 ✓；Ctrl+Z → 约束消失、重跑长回原样 ✓；
面板"负约束"页可改为"禁入并允许改道"（走廊 buffer 从边宽调到 1.5×，给细分绕行空间）。

**S-3 "昨天那版城更好，今天改崩了"**
恢复昨天的 Checkpoint（意图层整体回滚）→ 全量重算 → 与今天的手工改动差异列出在冲突页（今天的 adopted 对象不在昨日快照里，
恢复会被丢弃——**恢复前 dry-run 明确列出"将丢弃的今日固化对象"**，并提供"先把今日固化并入再恢复"选项）。

## 9. 模块内决策
| 编号 | 决策 | 备选 | 理由 |
|---|---|---|---|
| D-08-1 | 反悔的唯一入口是意图层；派生层不可撤销、只会随版本差重算 | 对生成结果做对象级 undo | 15k 实例 undo 栈不可行；且破坏确定性叙事 |
| D-08-2 | L1~L4 四层粒度 + `UndoHistoryTracker` 版本差联动 | 只给整城回滚 | 覆盖"一次拖动/一次批量/一块区域/一个里程碑"四类真实反悔 |
| D-08-3 | 编辑自动对象=adopt 或负约束，二选一由对象类型规则固定（§4.3） | 每次询问 | 弹窗打断心流；规则可背，toast+面板兜底 |
| D-08-4 | 自动流程永不删除/移动固化及以上对象，冲突转条目由用户裁决 | 自动挪位/静默删除 | 静默毁掉用户确认过的东西是这个工具最恶性 bug |
| D-08-5 | 锁区边界=派生隐形墙，参与周边细分但不进红线 | 锁区=整 chunk 黑箱 | 周边自动路网能沿锁区长出合理街区边界 |
| D-08-6 | 推荐顺序为 checklist 而非门禁，双路线（自上而下/自下而上）等价支持 | 流程表单强制顺序 | 创作工具常态是回头改；强制顺序逼人绕工具 |
| D-08-7 | 区域恢复不裁剪跨界对象，跨界列清单人工裁决 | 折线裁剪 | 裁剪撕裂真源、产生无数退化几何 |
| D-08-8 | 影响预览有触发阈值，默认不打扰；高危操作前自动快照 | 每步 dry-run / 不预览 | 弹窗疲劳与被毁之间取结构化中间点 |
| D-08-9 | journal/自动快照不入 git；检查点入 git | 全入 / 全不入 | 时序数据非真源；命名里程碑值得版本化 |
| **D-08-10** | **城心 = 独立意图锚点 `CityCenterAnchor`，场域经「设为城心」显式提交；S1a/07 衰减永不实时读场域位置**（09 H-7） | v2 旧案：实时派生 | 否则拖一个场域=近全链重算，手感与局部稳定双毁 |

| **D-08-13** | **`重新生成` 与 `新建城` 两个动作语义/按钮/确认强度全部分家；New City 必过影响预览+自动快照+二次确认+键入确认词**（09 H-16） | 合并成一个"生成"按钮 | 二者对人工层的后果正好相反；合并迟早毁掉用户成果且不可恢复 |
| **D-08-14** | **认回（reclaim）以 `BuildingRecordAsset` + `intentVersion` 为主依据（tag 仅剩 `slotKey` 反向指针、作首次兜底），`prev` 内存快照降级为优化；Tracker 首帧只建基线不触发重算**（09 H-10/H-10b → 定稿 11 §5/§6） | prev 落盘为快照资产 | 跨会话靠 prev 会静默叠楼毁 A-7/A-8；10 万对象遍历不可行，记录才是可伸缩真源 |

## 11. 风险
- **Tracker 合并窗口内的"半撤销感"**（用户连按 undo 时画面滞后一拍）→ 文案"等待历史稳定…" + 窗口内禁重复触发 Commit；实测手感不达标则降窗口至 100ms。
- 锁区+负约束+adopted 三者叠加后的意图层膨胀，恢复检查点时的 diff 变慢 → 检查点结构按对象 id 索引，diff O(变更数)。
- 边界墙参与细分会让锁区旁的自动路网"贴边成环"（视觉单一）→ 墙仅 Collector 级可见性，细分对墙端点吸附概率减半（03 §4.3 参数继承）。
- 用户误把 L1 当 L4（以为 Ctrl+Z 能回到昨天）→ 历史面板把四层显式分节展示，tooltip 每层注明能力边界；help 页放 S-1~S-3 走查。
- journal 恢复与 stableId 的耦合：若快照间 prefab/行被删除，恢复出的引用可能悬空 → 恢复时跑 06 §9 同款引用校验，悬空项列入冲突条目而非静默丢。
